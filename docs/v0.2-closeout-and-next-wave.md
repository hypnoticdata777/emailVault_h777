# v0.2 Closeout And Next Wave

This document marks the end of the first local-first implementation wave after
the product pivot from one-thread preservation into a Gmail offloader, inbox
cleaner, and portable email export tool.

## v0.2 Now Proves

- Export package contracts exist for Preserve, Clean Inbox, and Free Space
  modes.
- Sender-domain and category routing can plan safe folder paths before files
  are written.
- Synthetic classifier fixtures cover newsletter, automated/no-reply,
  bank/financial, human, attachment-heavy, and unknown mail.
- Deterministic classifier rules produce category decisions with evidence and
  review-required flags.
- Dry-run review planning can summarize a batch by category, sender domain,
  export path, and planned Gmail action.
- The local export package writer can produce raw `.eml`, metadata JSON,
  normalized text, trusted attachment files, and manifest JSON with checksums.
- Preserve Mode can run through the local export package writer and reuse the
  verified-storage plus completed-state audit boundary.
- Clean Inbox intent can be recorded after completed export while Gmail mutation
  remains disabled.

## Still Not Public-Live Ready

- The local export package Preserve Mode path is not exposed through a dedicated
  CLI, desktop UI, or add-on workflow.
- Clean Inbox intent is recorded at the coordinator layer, but no public review
  screen or add-on UX exposes it yet.
- The add-on still does not execute Gmail label, archive, mark-read, trash, or
  delete actions.
- Google OAuth, HTTPS deployment, add-on signing, and real Gmail validation
  remain private-environment work.
- Free Space Mode remains design-only beyond dry-run review and safe package
  planning.
- Synthetic walkthrough documentation now exists; screenshot assets are still
  optional future polish.

## Recommended Next Blockers

1. Public POC polish
   - Keep README/docs aligned as v0.2 complete foundation work.
   - Add screenshot assets only if useful for the public portfolio page.
   - Run a secrets/generated-artifacts sweep before any wider repo sharing.

2. Local Preserve Mode interface
   - Choose whether the first hands-on interface is CLI, local desktop UI, or
     add-on-triggered local API.
   - Expose user-selected export root.
   - Show generated package path and verification summary.

3. Clean Inbox review interface
   - Show dry-run category, sender, export path, and planned Gmail action.
   - Let the user approve only lower-risk items.
   - Continue recording intent while mutation remains disabled.

4. Private live validation
   - Select HTTPS deployment target.
   - Configure Google OAuth privately.
   - Validate signed add-on archive calls against a deployed API.
   - Decide mutation scopes and consent copy before any real Gmail cleanup.

5. Commercial/public split
   - Keep commercial SaaS implementation private before adding billing, hosted
     sync, real deletion, or commercial roadmap details.
   - Use public portfolio material for synthetic demo, architecture, and
     safety-first product story.

## Suggested Next Implementation Wave

The next build wave should not start with Free Space Mode. The safer order is:

1. Local Preserve Mode interface.
2. Screenshot assets from the synthetic walkthrough if useful.
3. Clean Inbox review surface with intent records.
4. Private deployed API plus OAuth validation.
5. Gmail label/archive/mark-read execution behind explicit review.
6. Free Space Mode trash/delete queue only after the above is proven.
